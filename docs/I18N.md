# Two languages

French is the default and keeps its URLs (`/recherche`). English lives under `/en` with translated first segments
(`/en/research`). The app renders both from the same routes in `src/app/[lang]/`.

| Public URL | Route rendered | How |
|---|---|---|
| `/recherche/x` | `/fr/recherche/x` | `src/proxy.ts` rewrites |
| `/en/research/x` | `/en/recherche/x` | `src/proxy.ts` rewrites |
| `/fr/recherche` | — | 308 to `/recherche` |
| `/en/recherche` | — | 308 to `/en/research` |

Segment names: `src/i18n/paths.ts` (`EN_SEGMENT`). Content slugs (publications, projects, themes) are shared.

## Links

Write internal links with the **French path**. `import Link from "@/i18n/Link"` (never `next/link`) turns it into the
right URL for the current language. `ButtonLink` already uses it. For a raw `<a>` or a string URL, use
`localePath(lang, "/recherche")` from `@/i18n/paths`.

## Reading the language

| Where | How |
|---|---|
| Server Component (no `"use client"`) | `const lang = await getLang()` from `@/i18n/server` — the component becomes `async` |
| Client Component | `const lang = useLang()` from `@/i18n/client` |
| Component used on both sides, or pure helper | take `lang: Lang` as a prop / argument |
| `generateMetadata` | `export const generateMetadata = () => pageMetadata({ path, fr: {...}, en: {...} })` |

`getLang()` comes from `next/root-params` and cannot be called at module level (only while rendering).

Accessibility labels shared across files: `getA11y()` (server), `useA11y()` (client) or `a11yFor(lang)`.

## Interface text

Keep text next to the component that shows it:

```tsx
import { copy } from "@/i18n/config";

const COPY = copy({
  fr: { title: "Publications", empty: "Aucune publication ne correspond." },
  en: { title: "Publications", empty: "No publication matches." },
});

export async function Thing() {
  const t = COPY[await getLang()];
  return <h2>{t.title}</h2>;
}
```

`copy()` makes TypeScript check that English has exactly the French keys. Values may be functions for counts:
`count: (n: number) => \`${n} outils\``.

The hooks reject literal `aria-label="…"`: use `aria-label={t.label}`.

## Content data

French data in `src/data/*.ts` stays the source of truth. English lives in **overlays** in `src/data/en/*.ts`: same
ids, only the translated fields. Facts (dates, DOIs, URLs, numbers, names) are never copied.

```ts
// src/data/en/publications.ts
export const EN_PUBLICATIONS: Record<string, Overlay<Publication>> = {
  "pub-2025-residual-fertility": { editorialTitle: "When sterility is not complete…", themes: ["Residual fertility", "SIT"] },
};

// src/data/publications.ts
export const publicationsIn = (lang: Lang) => localizeById(PUBLICATIONS, EN_PUBLICATIONS, lang);
```

Objects merge key by key, arrays item by item (`[{ label: "Link" }]` translates the label and keeps the URL).
A missing English entry falls back to French, and `tests/unit/i18n-content.test.ts` fails on it.

Small, UI-like data (navigation, labels of an enum) can hold both languages inline: `label: { fr, en }`.

Dates and numbers: `formatDate(iso, lang)` and `numberFormats(lang)` from `@/lib/utils/format`.

## Writing the English

- British spelling (modelling, behaviour, analyse, colour) and plain, precise scientific English.
- Translate meaning, not words; no claim that the French does not make.
- Keep the original language for sources that only exist in French (thesis title, French HAL titles) and mark the
  element `lang="fr"`.
- Standard terms: TIS → SIT (sterile insect technique), lutte biologique → biological control, biocontrôle →
  biocontrol, individu-centré → individual-based, réponse fonctionnelle → functional response, fertilité résiduelle →
  residual fertility, lâchers → releases, ravageur → pest, vulgarisation → outreach, communication orale → talk.
